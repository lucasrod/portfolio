## Problem

A prediction-market price can be read as a probability. Whether it is a good one is an empirical question: across many markets, do events priced at 30% happen about 30% of the time? PredDesk is a workbench for asking that question carefully, and for testing whether simple models of my own can improve on the market.

It is a research tool, not a trading system. It simulates; it never places real orders.

## Approach

- **Probability models.** An implied-probability model that removes the market's overround; a base-rate model with a Wilson confidence interval; a sequential Bayesian updater; and analyst overrides that must carry an explanation.
- **Signals.** A signal engine compares model estimates with market prices.
- **Simulation.** A paper broker accounts for fees and slippage, and a backtester replays market snapshots in time order.
- **Data.** An adapter normalises market data from Polymarket.
- **Architecture.** Domain logic has no dependency on the web framework or storage. Use cases sit above it, and a FastAPI app and a command-line interface sit on top. Storage is in memory for now.

## Results

The test suite passes: 301 tests, with 96% coverage, including property-based tests. That says the code does what its tests describe, not that its forecasts are good. No forecasting results are reported yet.

## Limitations

- The backtester's Brier score compares the entry price with whether the trade made money. That measures the strategy, not the calibration of the probability. It has to be scored against the event's actual outcome, with trading profit reported separately.
- The README describes PostgreSQL persistence and a web frontend; neither is implemented yet.
- Tests need `PYTHONPATH=src` to run, a packaging detail to fix.
